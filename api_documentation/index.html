    Authentication¶

    The API uses JWT (JSON Web Token) authentication. Include the access token in the Authorization header:

    Authorization: Bearer <access_token>

    User Roles¶

    • super_admin: Full system access
    • admin: Tenant administrator access
    • gamer: Regular user access

    1. Authentication Endpoints¶

    1.1 Register Gamer¶

    Purpose: Register a new gamer user for a specific tenant

    Endpoint: POST /auth/tenant/{tenant_id}/register/

    Auth Required: No

    Request Body: 

    {
  "username": "string",
  "email": "string (email)",
  "password": "string",
  "confirm_password": "string"
}
    Success Response (201 Created): 
    {
  "message": "Registration successful. Please verify your email."
}

    Error Response (400 Bad Request): 

    {
  "error": {
    "username": ["Username already exists."],
    "email": ["Email already exists."]
  }
}

    1.2 Login¶

    Purpose: Authenticate user and receive JWT tokens

    Endpoint: POST /auth/login/

    Auth Required: No

    Request Body: 

    {
  "email": "string (email)",
  "password": "string"
}

    Success Response (200 OK): 

    {
  "message": "OTP sent to email."
}

    1.3 Refresh Token¶

    Purpose: Obtain a new access token using refresh token

    Endpoint: POST /auth/refresh/

    Auth Required: No

    Request Body: 

    {
  "refresh": "string (JWT refresh token)"
}

    Success Response (200 OK): 

    {
  "data": {
    "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}

    1.4 Logout¶

    Purpose: Blacklist refresh token to log out user

    Endpoint: POST /auth/logout/

    Auth Required: Yes

    Request Body: 

    {
  "refresh": "string (JWT refresh token)"
}

    Success Response (200 OK):

    1.5 Verify Email¶

    Purpose: Verify user email address using token

    Endpoint: GET /auth/verify-email/?token={token}

    Auth Required: No

    Query Parameters: - token (required): Email verification token

    Success Response (200 OK): 

    {
  "message": "Email verified successfully"
}

    1.6 Forgot Password¶

    Purpose: Request password reset email

    Endpoint: POST /auth/forgot-password/

    Auth Required: No

    Request Body: 

    {
  "email": "string (email)"
}

    Success Response (200 OK): 

    {
  "message": "A reset link has been sent."
}

    1.7 Reset Password¶

    Purpose: Request password reset email

    Endpoint: POST /auth/reset-password/

    Auth Required: No

    Request Body: 

    {
  "token": "string",
  "password":"string",
  "confirm_password":"string"
}
    Success Response (200 OK): 
    {
  "message": "Password reset successful"
}

    1.8 Verify Login (OTP)¶

    Purpose: Verify login with OTP

    Endpoint: POST /auth/verify-login/

    Auth Required: No

    Request Body: 

    {
  "email": "string (email)",
  "otp": "string (6 digits)"
}

    Success Response (200 OK): 

    {
  "data": {
    "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}

    1.9 Resend Verification¶

    Purpose: Resend email verification link

    Endpoint: POST /auth/resend-verification/

    Auth Required: No

    Request Body: 

    {
  "email": "string (email)"
}

    Success Response (200 OK): 

    {
  "message": "Verification mail sent."
}

    2. User Management (Admin)¶

    2.1 List Users¶

    Purpose: Get paginated list of all users

    Endpoint: GET /users/

    Auth Required: Yes (super_admin, admin)

    Query Parameters: - page (optional): Page number (default: 1) - page_size (optional): Items per page (default: 10) - status (optional): Filter by status (active, deleted)

    Success Response (200 OK): 

    {
  "count": 4,
  "page": 1,
  "page_size": 10,
  "next": null,
  "previous": null,
  "data": [
    {
      "id": "uuid",
      "username": "string",
      "email": "string",
      "first_name": "string",
      "last_name": "string",
      "is_active": true,
      "created_at": "2025-12-31T14:06:07.196292Z",
      "updated_at": "2025-12-31T14:06:07.196298Z"
    }
  ]
}

    Error Response (403 Forbidden): 

    {
  "error": "You do not have permission to perform this action."
}

    2.2 Get User¶

    Purpose: Get details of a specific user

    Endpoint: GET /users/{id}/

    Auth Required: Yes (super_admin, admin)

    Path Parameters: - id (required): User UUID

    Success Response (200 OK): 

    {
  "data": {
    "id": "uuid",
    "username": "string",
    "email": "string",
    "first_name": "string",
    "last_name": "string",
    "is_active": true,
    "created_at": "2025-12-31T14:06:07.196292Z",
    "updated_at": "2025-12-31T14:06:07.196298Z"
  }
}

    2.3 Create User¶

    Purpose: Create a new user (admin only)

    Endpoint: POST /users/

    Auth Required: Yes (super_admin, admin)

    Request Body: 

    {
  "username": "string",
  "email": "string (email)",
  "password": "string",
  "confirm_password": "string",
  "tenant": "uuid (tenant ID)"
}

    Success Response (201 Created): 

    {
  "message": "Verification mail sent."
}

    2.4 Delete User¶

    Purpose: Soft delete a user

    Endpoint: DELETE /users/{id}/

    Auth Required: Yes (super_admin, admin)

    Path Parameters: - id (required): User UUID

    Success Response (204 No Content): 

    (Empty response body)

    2.5 Disable User¶

    Purpose: Disable/enable a user account

    Endpoint: PATCH /users/{id}/

    Auth Required: Yes (super_admin, admin)

    Path Parameters: - id (required): User UUID

    Request Body: 

    {
  "is_active": false
}

    Success Response (200 OK): 

    {
  "data": {
    "id": "uuid",
    "username": "string",
    "email": "string",
    "first_name": "string",
    "last_name": "string",
    "is_active": false,
    "created_at": "2026-01-01T20:52:55.715907Z",
    "updated_at": "2026-01-01T21:05:37.380412Z"
  }
}

    2.6 Restore Deleted User¶

    Purpose: Restore a soft-deleted user

    Endpoint: POST /users/{id}/restore-user/

    Auth Required: Yes (super_admin, admin)

    Path Parameters: - id (required): User UUID

    Success Response (200 OK): 

    {
  "message": "User restored successfully."
}

    Common Error Responses¶

    400 Bad Request¶

    Invalid request data or validation errors.

    {
  "error": {
    "field_name": ["Error message"]
  }
}

    401 Unauthorized¶

    Missing or invalid authentication token.

    {
  "error": "Authentication credentials were not provided."
}

    or

    {
  "error": "Invalid or expired token."
}

    403 Forbidden¶

    User doesn't have permission to access the resource.

    {
  "error": "You do not have permission to perform this action."
}

    404 Not Found¶

    Requested resource doesn't exist.

    {
  "error": "Not found."
}

    500 Internal Server Error¶

    Server encountered an unexpected error.

    {
  "error": "Internal server error."
}
